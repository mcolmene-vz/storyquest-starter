## Disclosed items

- Simulator-only messages, same four lines in every run: URP "Shadowmap RenderTexture requested without a depth buffer" (once), ASTC decompression warnings (simulator GPU). No errors or exceptions in any simulator player log.
- "Coins lost: 0" on a Normal defeat in M1: a lost battle has earned no coins yet; wording is a polish question for M5.
- No projectile for Archer or Mage (producer ruling 2026-10-16, BACKLOG row, revisit at M4 sign-off).
- Target size in the action shot is ~20 % of frame height; the architect's note: if a kid tester cannot read the hit, the fix is an attacker step-in in M2, not a camera number.
- Build-tool notes recorded in DEVICE-TESTING: Append refusal on an empty folder, Burst references when a simulator build follows a device build, the one-time symbols copy failure on a new iOS version.
- `ProjectSettings.asset` drift, found at sign-off: `BuildPipeline.ApplyPlayerSettings` writes the iOS graphics-API list as explicit (`m_Automatic: 0`, Metal only, since M1-D3), but the M1-D4 commit carried `m_Automatic: 1`. Regeneration rewrote that line in the lead's final check and the earlier "tree clean" note missed it. **Correction 2026-10-16 (found in M2-D4):** the sign-off commit 6a8bcda did *not* take the generator's value, though its message says it did. The lead ran the test gate after the regeneration and before staging; that editor launch wrote `m_Automatic: 1` back, and 6a8bcda carries 1. The line flips with whichever command ran last (`ProjectSetup.Run` writes 0, an editor launch writes 1). It is with the architect. No effect on any build: `BuildIOS` applies the explicit Metal list itself, and iOS uses Metal either way.
